# 安装、启动与恢复

本文描述源码中待下一次构建发布的 Windows 本地工具包。现有已安装版本尚未同步本轮原生控制改动，请以实际运行版本为准；新的组合键与完整客户端画面仍待真人验证。统一入口是 **`NadeLab.cmd`**。独立训练服务器管理员见 [服务器部署](server-guide.md)。

## 第一次安装

准备一份 Steam 安装的 CS2。安装时关闭 CS2，并等待 Steam 完成游戏更新。默认原生模式不需要选择或修改 Steam 按键资料；兼容模式需要先正常启动并退出一次游戏，让账号生成自己的配置。

1. 将工具包完整解压到**较短的全英文路径**，例如 `D:\NadeLab`，保留包内目录结构。路径可含空格，不能含中文或其他非 ASCII 字符；安装器会在复制大量资源前检查。不要把工具直接解压进 CS2 游戏目录。
2. 双击 `NadeLab.cmd`，选择安装。自动发现失败时，选择包含 `game/` 的 CS2 安装根目录。
3. 默认采用本地输入模块，保留个人绑定。只有主动选择旧快捷键兼容模式时，才选择需要训练的 Steam 资料；不能用另一个账号的键位作为恢复备份。
4. 等待安装完成。工具按固定版本和校验值从官方来源准备运行框架，并创建独立训练实例；不要求安装 Python、.NET SDK 或 Workshop Tools。
5. 选择 **2 进入训练**。工具先检查客户端资源，再确认训练服就绪，随后启动输入模块，通过 Steam 启动 CS2 连接本地训练服，不加载旧快捷键。新启动的无人空闲实例会检查实际地图、插件、训练开关和原生碰撞；复用实例时只读取状态。选择 **8 仅启动训练服** 可保留手动进入方式。

首次准备需要网络下载框架。CS2 游戏内容来自自己的安装目录，不包含在工具压缩包中。跨卷资源准备可能需要复制较多文件，请保留足够空间并等待完成。

当前 Metamod 在中文训练实例路径下可能无法打开插件目录，即使该目录实际存在，首版因此限制工具安装路径。英文 Steam 游戏源路径已测试，中文 Steam 游戏源路径尚未实测，建议首版使用英文源路径。

Windows 自带 PowerShell 5.1 的文件操作也有路径长度限制。工具会提前检查依赖解压和实例目标路径；若提示路径过长，请移至较短目录后重试，不要把它放在多层下载文件夹内。

默认安装不设置功能键入口、不重绑滚轮，也不改写个人按键、平台配置和日常 `autoexec.cfg`。专用 UI 随工具安装，`nadelab_keys.cfg` 默认是只有原生模式命令、没有绑定命令的安全入口；旧 autoexec 中即使仍有 `exec nadelab_keys`，更新后也不会因此重新安装旧快捷键。

从旧版更新时，安装器按匹配的安装记录恢复仍由 NadeLab 占用的键，保留后来另行设置的命令，归档原记录后进入原生模式。必须有对应资料、对应按键的可靠原值；缺少证据时不猜默认键，按恢复报告核对。另行修改过的客户端资源会作为冲突保留。

## 进入训练

使用「进入训练」且 CS2 原本未运行时，工具通过 Steam 的本次启动参数连接训练服，不修改 Steam 的永久启动选项。若出现区服选择窗口，按平时的选择点击“开始”。已验证 Steam 能拉起客户端启动窗口；启动后的自动连接及完整客户端画面流程仍待验收。

CS2 已经在运行时，工具不会关闭或重复启动它。此时，或使用「仅启动训练服」时，开启游戏开发者控制台，执行显示的命令。默认端口下为：

```text
connect 127.0.0.1:27025
```

端口自定义时使用启动器报告的地址。服务器已经运行时，重复启动只检查已有实例，不应让第二个服务争用端口。

进入地图后，F1 菜单，滚轮 / ↑↓ 选择，E 确认，R 返回；WASD 保持移动。F3 循环道具，Shift+R 换站位、Shift+E 重选目标。菜单打开时拦截个人切武器/道具键，关闭后滚轮保留原功能。完整说明见 [玩家手册](player-guide.md)。仅启动服务器不会启动输入模块，可重新选择进入训练；备用聊天入口 !nl。

## 离开训练与恢复按键

默认原生模式不安装训练键位，离开训练无需还原个人绑定。断开后可选择停止训练服；工具只管理自己的实例，普通客户端由你正常退出。更新 CS2 前先停训练服，避免资源占用。

如需移除客户端 UI 和专用配置，退出 CS2 后在 `NadeLab.cmd` 中选择恢复客户端。工具按安装记录恢复或移除所管理的文件，保留后续修改并报告冲突，不删除训练数据。原生安装的恢复不需要读取个人按键资料。

旧版或兼容模式的恢复会逐键检查：仍为记录中 NadeLab 命令的键恢复原值，后来改成其他命令的键保留。请保留 `release-state/` 中的原始记录和备份；不要用整份旧按键文件覆盖当前资料，也不要跨账号恢复。

研发安装器的 `--restore-native --dry-run` 可预览依据历史记录能够恢复的键；实际恢复还会把旧配置入口替换成无绑定的原生入口。仅有完整文件备份、没有该键实际改写记录时，不据此认定原值。日常 autoexec 保持原样；若其中直接写有旧 `bind` 命令，需逐项确认历史归属，工具不会批量删除个人命令。

## 可选：旧快捷键兼容模式

只有需要旧方案时，退出 CS2 后明确运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Install -LegacyBindings
```

多个资料时交互选择，或通过 `-KeysFile '<所选账号的 cs2_user_keys_0_slot0.vcfg 路径>'` 指定工具发现的资料。兼容安装保存原值，为所选账号设置 F1 入口；若更新时 F1 已被你另行改过，会保留并提示。此模式的启动才会加载含 14 个绑定的配置：F1–F9、滚轮上 / 下、↑ / ↓ 与 V。重新加载配置会覆盖这些键，包括个人滚轮跳等用途。

需要恢复兼容键位时，优先退出游戏后使用工具的恢复入口，以保留安装后的个人改动。控制台 `exec nadelab_restore_keys` 只适用于生成该配置的账号，会按安装时原值恢复，不能判断你后来改过哪些键；不要把它加入 autoexec。切回默认原生模式可退出游戏后重新运行安装，不加 `-LegacyBindings`，由安装记录恢复旧键并安装无绑定的原生入口。

## 更新与搬迁

1. 停止训练服，退出 CS2。
2. 备份 `release-state/`、`instance/` 中的插件 `data/` 和自定义 `physics.json`。保留原包，便于回退。
3. 用新版本文件更新工具目录，保留本地状态和玩家数据，再运行安装及启动检查。不要拿研发目录中的零散 DLL 混配发布版 UI。
4. 客户端重新启动后使用自己的动作键打开菜单。更新游戏或框架后，即使启动检查通过，也先做一次简单手投确认。

搬迁目录前先停止实例。安装状态可能记录旧位置；不要只复制运行中的服务器或修改状态文件里的路径。最稳妥的办法是在新的全英文路径重新安装，再迁移自己的插件数据；旧目录暂时保留到新环境确认正常。

## 目录用途

| 目录或文件 | 用途 |
| --- | --- |
| `NadeLab.cmd` | 安装、启动、状态与恢复入口 |
| `scripts/release/` | 发布工具的运行脚本 |
| `game/` | NadeLab 插件、配置和预编译界面资源 |
| `instance/` | 本机独立训练服与运行数据 |
| `release-state/` | 安装记录、下载及恢复备份；不要公开上传 |
| `docs/release/` | 当前版本的玩家与管理员文档 |

卸载前先停止服务、退出 CS2，并完成客户端恢复。随后可移除工具目录；先另存需要保留的投法和记录。不要直接删除安装备份后再尝试恢复客户端。

## 常见问题

| 现象 | 下一步 |
| --- | --- |
| 提示工具路径不能包含中文，或框架报告无法打开目录 | 换到全英文工具目录后安装，空格可以保留；不要只改最末一级目录，完整路径都需符合要求 |
| 找不到 CS2，或兼容模式找不到账号资料 | 确认 Steam 游戏安装完整并选择正确安装根目录；兼容模式还需先正常启动并退出一次 CS2 |
| 下载或校验失败 | 保留报错，恢复网络后重试；不要跳过校验或用未知来源的框架替换 |
| 启动未就绪 / 插件未加载 | 用入口查看状态，保留具体错误；确认 Steam 已更新完成，框架与包版本匹配 |
| 连接后没有菜单 | 从进入训练启动输入模块并连接已更新的训练服，按 F1；备用聊天 `!nl`。UI 更新后重开游戏，不要反复覆盖个人绑定 |
| 文本缺失、布局异常 | 确认客户端与服务器使用同版 UI，重开 CS2；仍有问题时附分辨率和截图反馈 |
| 使用键没有记录新站位 | 已有站位时沿用它；换站位用静步＋使用，先关闭菜单、飞行和聊天，落地停稳 |
| 没有搜索到路线 | 继续搜索、调整实际可接受区域或换站位；搜索失败不证明无解 |
| 恢复时报告冲突 | 工具保留了后续修改；根据恢复报告逐项核对，不要用整份旧配置覆盖新设置 |
| 旧 autoexec 仍调用训练配置 | 默认更新安装无绑定原生入口；autoexec 本身保持原样。若有直接写入的旧 bind，按对应记录逐项核对，保留个人命令 |

## 可选命令行

通常使用 `NadeLab.cmd` 即可。自动化部署可调用同一入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Verify
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Play
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Install -GameInstallation '<CS2安装根目录>' -Port 27025
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Start -Map de_train
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action Stop
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/release/NadeLab.ps1 -Action RestoreClient
```

端口在安装时设置，启动沿用已安装实例的端口。只有旧快捷键兼容模式需要选择账号；该模式的多个账号非交互安装可用 `-KeysFile '<所选账号的 cs2_user_keys_0_slot0.vcfg 路径>'` 指定资料；需要是工具发现的 Steam 资料。`-NonInteractive` 用于已经明确指定参数的流程，缺失选择会报错。服务器专用安装可用 `-ServerOnly` 跳过客户端文件；`-Action Uninstall` 提供停服与客户端恢复，保留数据供自行备份后移除。具体参数以同包脚本为准。
